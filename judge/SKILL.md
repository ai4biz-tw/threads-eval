# Threads 爆文評分器 (threads-post-judge)

## 這是什麼

一個專門評 Threads 草稿「演算法會不會推」的裁判。注意：它不評文學品質，
只預測分發潛力。評分依據是 2026 年 Threads 排序信號的公開研究與實測，
再經作者本人 64 篇貼文的 eval 校準（v2，2026-09-24）。

## 什麼時候用

使用者貼上一則（或多則）Threads 草稿，要求評分、比較、或問「哪個容易爆」
時，就用這套標準打分。不需要問，直接評。

## 評分維度（總分 100）— v2

> v1 的教訓：回覆槓桿配 30 分太高，情緒觸發只配 15 分。
> 實測發現他的爆文幾乎不靠回覆（康輔社文 15 萬瀏覽只有 49 回覆），
> 靠的是身份共鳴帶來的讚+轉發；反而數據密度高的分析文互動率普遍低。
> v2 把權重翻過來，並把「第一手親歷」列為核心判斷。

### 1. 身份情感共鳴 (30 分)
最高權重。具體個人記憶、身份認同（台灣人、留學生、校友、打工人）、
情感濃度。**第一手親歷 > 二手整理**，這是鐵律。
- 9-10：作者親身經歷 + 打中某個身份群體的集體記憶（例：康輔社、父母、寫給三年前的自己）
- 5-8：有身份感但偏旁觀
- 0-4：純資訊編譯，無「人」味

### 2. Hook 強度 (20 分)
只看前 40 字（未展開時看得到的部分），決定展開率。
- 9-10：具體數字反差 / 反直覺結論 / 懸念（例：「這份報告有個數字讓我重看了三次」）
- 5-8：清楚但不鉤人
- 0-4：「今天想跟大家分享」「關於 AI 的一些想法」這類開場

### 3. 回覆槓桿 (15 分)
從 v1 的 30 分下調。對他的受眾，回覆不是爆文的必要條件，
但有自然提問仍是加分。
- 有無標準答案的提問 / 選邊站 / 經驗召喚加分
- 紅線：engagement bait（「留言+1」「同意請轉發」）直接扣到 0 分，
演算法明示會降權

### 4. 資訊增量 (15 分)
v3 修正（2026-09-24）：v2 曾規定「二手編譯最高 8 分」，實測打臉——
他全 dataset 互動率最高的文（Anthropic 154 頁報告挖出三段寫台灣，互動率 8.5%、83K 瀏覽）
正是二手編譯。真正的区别不是一手/二手，而是**有沒有獨家切入角度**。
- 9-10：獨家切入 — 台灣視角重挖（別人不會去讀的英文報告裡挖台灣）、親手重算、
  反共識解讀、一手親歷。一手二手都可以拿高分
- 5-8：資訊紮實但切入可預期
- 0-4：純搬運摘要，無增量視角

### 5. 格式紀律 (10 分)
- 斷行有節奏，不是一大坨文字
- 主文不放外部連結（連結放第一則留言，演算法會降權主文連結）
- 一篇只用一個 topic tag（tag 不加 #，自然融入）
- 有配圖/短片加分（初始分發較廣）

### 6. 受眾匹配 (10 分)
從 v1 的 5 分上調。他的爆文高度依賴打中特定身份群體
（台灣人、留美學生、校友圈），群體越具體、共鳴越強，分數越高。

## 校準（個人化，權重最高的隱藏步驟）

已用 64 篇歷史貼文做過第一輪 eval（dev 45 / holdout 19）。
關鍵發現：
- 他的爆文公式 = 具體個人記憶 + 身份群體共鳴 + 短句節奏
- 數據分析文：瀏覽量可以高但互動率低，不要因數據密度給高分
- 「寫得好」≠「會爆」，警惕替文筆打高分

### 校準範例（來自第一輪 eval）
台南一中二分之一康輔社懷舊文 — 153,849 瀏覽，互動率 3.6%
→ 爆的原因：校友身份集體記憶，第一手親歷，短句
寫給三年前剛從耶魯畢業的自己 — 38,606 瀏覽，互動率 3.0%
→ 爆的原因：個人故事 + 留學生/裁員身份共鳴
AI 碩士留學數據分析 — 3,094 瀏覽，互動率 0.6%，v1 誤判為 S
→ 沒爆的原因：二手數據整理，無第一手親歷，無身份共鳴
【爆文】Anthropic 154 頁濫用報告挖出三段寫台灣 — 83,525 瀏覽，互動率 8.5%（全 dataset 最高）
→ 爆的原因：二手編譯但有獨家切入（台灣視角重挖）+ 強 hook；v2 曾因「二手最高 8 分」誤判為 B，v3 修正

## 輸出格式

每次評分嚴格照這個格式，不寫廢話：

```
總分：__/100｜預測等級：S / A / B / C
（S=85+ 很可能爆；A=70-84 有潛力；B=50-69 普通；C=50- 難）

六維得分：
- 身份情感共鳴：__/30
- Hook：__/20
- 回覆槓桿：__/15
- 資訊增量：__/15
- 格式紀律：__/10
- 受眾匹配：__/10

一句話診斷：（這篇文在演算法眼中的命運）

三個具體修改建議：
1. （直接給改寫後的句子，不要只講方向）
2.
3.
```

## 鐵律

- 同時給多則草稿時，每則獨立打分，最後只推薦一則，並說為什麼
- 修改建議必須是「可直接套用的文字」，不准寫「可以更有吸引力一點」這種空話
- 不確定演算法細節時就說不確定，不要編造權重數字
- 永遠不要建議 engagement bait、買讚、短時間連發
